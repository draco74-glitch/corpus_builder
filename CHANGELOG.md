## [0.2.1] — 2026-08-30

Исправления по итогам полного ревью репозитория (7 критических, 12 важных,
8 мелочей). Ниже — user-visible изменения; внутренние фиксы помечены кодами
находок (C/I/M из отчёта ревью).

### Fixed — данные

- **Фильтр качества больше не сжигает корпус** (C1). Удалено правило
  «текст длиннее 200 символов без технических слов = спам»: с дефолтным
  `spam_check: true` оно отбраковывало ЛЮБОЙ нелектронный текст (и даже
  страницы про I2C/резисторы). Спам теперь определяется только по явным
  признакам рекламы, а в `rejected_by_reason` попадает конкретная причина
  (`spam:commercial`, `too_short`, `duplicate`, …) вместо `unknown`.
- **Пост-обработка не падает на повторяющемся `source_url`** (C3):
  `MinHashLSH` больше не ключуется URL (`ValueError: The given key already
  exists` убивал весь `postprocess`).
- **Записи без URL и «одинаковый URL, разный текст» больше не молча удаляются**
  (C4): дедупликация оперирует позициями записей; при коллизии URL оригиналом
  становится более длинная запись; пустой `source_url` в URL-дедупе не участвует.
- **`resume=False` перезаписывает корпус, а не дописывает в него дубли** (C6);
  `--dry-run` не трогает собранные файлы.
- **PII-фильтр: контекст вместо резки технических чисел** (I12). `192.168.1.1`
  без слова про сеть/IP, `1.22.331.4`, парт-номера `123-45-6789` и группы
  задержек остаются в датасете; недвусмысленные форматы (`+7 (495) …`,
  `8 800 …`, `+1-555-…`) и обфусцированные e-mail вырезаются ПОЛНОСТЬЮ
  (раньше адрес оставался читаемым). Прежнее «агрессивное» поведение —
  `finetune.pii_aggressive: true` или `remove_pii(..., aggressive=True)`.
- **Markdown-шаблоны без лишнего `{}`** (I13/I20): если ни один вариант промпта
  не подходит по набору placeholder'ов, генерируется чистый текст из аргументов,
  а не сырой шаблон с `{content}` внутри обучающей выборки.
- **Пары StackExchange извлекаются и из русских, и из английских тредов** (I14),
  тело принятого ответа берётся из `metadata` (однозначно), а не из разборки
  заголовков.
- **Экспорт не теряет данные краулера** (I15/I16): Parquet хранит `metadata` и
  `downloaded_files`, `NULL` остаётся `NULL` (раньше `quality_score: None`
  превращался в `0.0`); `dataset_infos.json`/карточка описывают фактические
  колонки и фактические языки, обещание «loading script» убрано.
- **`balance_by_type`**: `max_per_type: 0` = без ограничения, а потерянные
  пары видны в статистике (`dropped_by_type`), балансировка больше не
  «невидимо» режет меньше-не-нужные классы (I16).

### Fixed — краулинг

- **Все 9 типов источников конфигурируемы** (C2): `type: arxiv|doaj|crossref|
  wikipedia` больше не отбивается валидацией (`config.yaml` их просто не
  принимал), и `detect_source_type` в мастере различает wiki/arXiv/DOI/DOAJ,
  а не пишет всем `html`.
- **Async-краулинг вежлив так же, как синхронный** (I1): общий session из
  config (User-Agent, пул, ретраи, кэш, прокси), rate limiter, per-URL
  таймаут, чекпойнты `save_checkpoint_every`, корректный `should_stop`;
  заблокированные по robots.txt домены отсекаются параллельным pre-filter'ом
  в обоих путях.
- **HTTP-кэш реально подключён** (I2): `make_cached_session` с TTL из настроек
  и теми же retry/pool, что и обычная сессия.
- **Настройки приложения доходят до движка** (I4/I5): чекбоксы async,
  gzip/parallel postproc, streaming/incremental dedup, cache/TTL,
  `respect_robots_txt`, browser-заголовки и прокси-ротация теперь имеют
  потребителя; импорт JSON настроек приводит типы и не может «отравить»
  ран (`per_url_timeout_minutes: "ten"` больше не долетает до краулинга),
  модели с `validate_assignment`.
- **Per-source `include_files` / `download_files` работают** (I7); раньше поля
  принимались конфигурацией и молча игнорировались.
- **GitHub**: вики берётся из `{repo}.wiki` (раньше — из архива самого репо),
  архив качается на диск с лимитом `max_archive_mb` вместо двух копий в RAM,
  issues пагинируются и дополняются комментариями (`issues_comments_max`),
  LFS-указатели и дубли docs/ не попадают в контент (I8/I9).
- **PDF**: вёрстка «в две колонки» определяется по бимодальному признаку и
  **постранично** — раньше одноколоночные документы распознавались как
  двухколоночные, и блоки переставлялись; таблицы парсятся одним проходом
  pdfplumber; документ закрывается в `finally`; без tesseract «фильтр схем»
  не сохраняет все картинки подряд (I10/I11/I12).
- **StackExchange**: `site` из URL разбирается корректно
  (`ru.stackoverflow.com` → `ru.stackoverflow`), списки
  `/questions/tagged/<tag>` краулятся, а не отваливаются с «no record»;
  причина сбоя попадает в `errors.jsonl` (I11).
- **`is_blocked_url`** больше не режет обычные страницы из-за подстроки в query
  (`?v=2024.03.ts`) и не блокирует `cloudflare.com` / `cdn.jsdelivr.net` (I11).
- **Кэш скачанных файлов** сверяет размер с сервером (HEAD), иначе вечная
  первая версия документа (I5). Отключается:
  `output.revalidate_cached_files: false`.

### Fixed — авто-обновление и GUI

- **Toast-уведомления работают** (C5): фабричный метод переименован в
  `display()` — прежний `show` перекрывал `QWidget.show()`, и любое уведомление
  падало с `TypeError`; в `gui.py` добавлен модульный логгер (раньше обработчик
  ошибок сам падал с `NameError: name 'log' is not defined`).
- **Целостность обновлений** (C7): релизный ассет ставится только при
  совпадении SHA256 sidecar'а (`require_digest=False` — осознанный override),
  молчаливая запись файлов «в никуда» закрыта через staging +
  `verify_member_path` (Zip Slip), маркер комитета двигается только при
  полностью успешном обновлении, частичный сбой откатывается на бэкап,
  `--branch` конструктора действительно используется.
- **`closeEvent`** даёт осмысленный выбор «в трей / остановить и выйти /
  отмена» вместо `Cancel|Yes`, и ждёт поток до 5 секунд (I9-Minor).
- **`_build_effective_config` не мутирует загруженный конфиг** (I9): выбор
  output-папки больше не «прирастает» к объекту, и worker не читает
  изменяемый GUI объект.
- **`run_postprocess` слышит `should_stop`** (I10).
- `state.json`/`errors.jsonl`/`crawl.log` по умолчанию пишутся рядом с
  `corpus_file` (уравнение путей с GUI, I9).

### Changed

- **Единая лексика `task_type`** для обоих путей генерации пар (пост-обработка
  корпуса и окно Fine-Tuning): `article_to_summary` → `article_summary`,
  `summary_to_article` → `article_expansion`, `code_to_explanation` →
  `code_explanation`, `datasheet_to_specs` → `datasheet_specs`,
  `datasheet_to_structure` → `datasheet_structure`. Раньше один и тот же тип
  пары подписывался по-разному в зависимости от того, какой кнопкой его собрали.
- **Тексты промптов взяты из `prompt_variations`** (и, соответственно, из
  `prompts.yaml`), а не зашиты кириллицей в `extract_pairs.py`; для
  «обратных» типов добавлены варианты (`article_expansion`,
  `description_to_kicad`, `datasheet_structure`) (I14).
- **Пара «код → объяснение» строится на настоящем объяснении**: completion —
  текст, которым автор окружил блок кода, а не шаблонная фраза «Этот код
  написан на {language}. Контекст: …».
- **Wiki GitHub** берётся из `{owner}/{repo}.wiki` и не дублирует файлы, уже
  попавшие в контент (I8).
- Экспорт окна Fine-Tuning пишется в `finetune_pairs.jsonl`, чтобы не затирать
  `instruction_pairs.jsonl` предобучающего пайплайна при выборе той же папки (I13).
- Финальный скор ревью: `python -m ruff check` — с 711 замечаний до ~370
  (удалены мёртвые импорты, дубли ключей, неиспользуемые переменные,
  исправлены `F821`/`F601`/`B033`).

### Removed

- Дубль `make_session` в `http.py` (копия `robots.make_session`).
- Дубли ключей в словарях локализации RU/EN (18 записей).
- Мёртвые `AutoUpdater._compare_versions` и другие неиспользуемые импорты
  (`ruff`-проход по safe-правилам).

### Fixed (финальная самопроверка)

- **OCR PDF больше не трогает `fitz.Document` из пулов**: документ PyMuPDF
  не тредобезопасен, поэтому страницы рендерятся последовательно в основном
  потоке, а параллелится только вызов tesseract (`_render_page_png` +
  `_ocr_png_safe`).
- **Стриминг/инкрементальная дедупликация считают индексы так же, как
  `iter_records`** (битые/пустые строки не сдвигают нумерацию) — иначе
  `duplicate_of` указывал бы не на ту запись.
- **`robots_fail_open` + `ignore_robots`**: отказ robots.txt (например, 403 у
  StackExchange на сам `/robots.txt`) больше не «съедает» источник молча —
  источник пропускается с предупреждением, не помечается обработанным, и для
  API-краулеров есть явный `sources[].ignore_robots: true`.
- **Кэш скачанных файлов** сверяется по размеру только когда файл «протух»
  (`output.cache_ttl_hours`), чтобы не удваивать число запросов на корпус с
  тысячами картинок.
- `is_httpx_available()` больше не импортирует тяжёлый модуль ради проверки.

### Notes

- Изменения поведения — см. таблицу «Migration notes» в README — часть фиксов
  меняет выход пайплайна (имена `task_type`, перезапись корпуса при
  `--no-resume`, кэш скачанных файлов).

### Docs

- `config.example.yaml` описывает все новые/реально работающие ключи;
  README: разделы Auto-Update и Performance Optimizations приведены в
  соответствие коду (что подключено, чтоexperimental).
- Тесты: `tests/cassettes/` с записанными ответами, маркер `network`
  (по умолчанию пропускается, `--run-network` включает), `tests/conftest.py`
  с `REPO_ROOT` — набор больше не зависит от текущей директории;
  ~115 новых регрессионных тестов на перечисленные фиксы.


## [0.2.0] — 2026-08-08

### Added
- **One-dir архитектура** — запуск в 10x быстрее, авто-обновление без пересборки
- **Авто-обновление по коммитам** — подтягивание .py файлов из GitHub main
- **8 типов источников**: HTML, PDF, GitHub, StackExchange, DOAJ, arXiv, Crossref, Wikipedia
- **14 оптимизаций производительности** (7x ускорение):
  - Асинхронный aiohttp-краулинг (4-6x)
  - Параллельный OCR для PDF (10-20x)
  - Multiprocessing пост-обработка (3-5x)
  - SQLite WAL для HTTP-кэша (1.4x)
  - Streaming MinHash для больших корпусов
  - Incremental dedup с сохранением LSH-индекса
  - Memory-mapped чтение для файлов >1 ГБ
  - Сжатие JSONL на лету (.jsonl.gz)
- **Расширенные фильтры качества**:
  - fasttext-langdetect (язык)
  - kenlm perplexity (опционально)
  - Спам/токсичность фильтр
  - Code/text ratio с извлечением блоков кода
- **GitHub-краулер**: Issues/PR, Wiki, docs/ directory
- **PDF-краулер**: двухколоночная вёрстка, pdfplumber таблицы, фильтр схем
- **4 типа SFT-пар**: datasheet→specs, article→summary, code→explanation, FAQ Q&A
- **GUI: 15 улучшений интерфейса** (A-O):
  - Drag-and-drop config.yaml
  - Контекстное меню на записях
  - Поиск по логу (Ctrl+F)
  - Toast-уведомления
  - 5 тем оформления (dark, light, Material Blue/Green/Purple)
  - Превью KiCad-файлов
  - История недавних config.yaml
  - Прогресс с ETA
  - Сравнение корпусов (diff dialog)
  - Встроенный YAML-редактор
  - Dashboard с метриками
  - Мастер первого запуска
  - Локализация RU/EN
- **Единое окно настроек** — 10 вкладок со всеми опциями программы
- **Мастер создания config.yaml** — Excel → BFS-обход → готовый конфиг
- **Защита от видеопотоков** — блоклист 30+ расширений и 20+ доменов
- **Экспорт**: HuggingFace dataset, Parquet (zstd), HTML diff-отчёты
- **166 unit-тестов**, все проходят

### Fixed
- Loguru crash в PyInstaller windowed mode (sys.stderr = None)
- kenlm не собирается на Python 3.13+ — сделан опциональным
- PySide6 не устанавливается на Python 3.14 — pin requires-python <3.14
- Краулинг зависает на страницах с видео
- Кнопка «Создать config.yaml» не работала из-за asyncio event loop на Windows

## [0.1.0] — 2026-08-06

### Added
- Базовый пайплайн: краулинг → дедупликация → нормализация → качество
- 4 типа источников: HTML (trafilatura), PDF (PyMuPDF), GitHub, StackExchange
- Resume после сбоя через state.json
- robots.txt + per-domain rate limiter
- Дедупликация: точная (sha1), MinHash (LSH), по URL, по изображениям
- Нормализация: NFKC + ftfy + zero-width + ё→е
- CLI: crawl, postprocess, stats
- 56 unit-тестов
